# Flutter Boilerplate

Flutter workspace template (Dart pub workspace): apps for iOS, Android and web plus shared packages. Riverpod, go_router, gen-l10n, Material 3.

## Commands

All Flutter and Dart commands go through `fvm` (the Makefile does this for you). Run everything from the repo root. `make check` is the local gate: run it before finishing any change. There is no remote CI; the pre-push hook runs the same command.

| Command | What it does |
|---|---|
| `make setup` | `fvm install`, `pub get` at the root, git hooks if `lefthook` exists |
| `make check` | format check, `analyze`, architecture + dependency check, locale parity, agent index freshness, tests in every member |
| `make dev` | run an app (`APP=mobile` by default; reads `.env.json` as `--dart-define-from-file` if present) |
| `make index` | regenerate the index of shared code in AGENTS.md (run it after adding or changing public declarations in `app_ui`, `app_shared` or a feature's `application/`) |
| `make test` / `fmt` / `analyze` | the single steps |
| `make e2e` | `integration_test` smoke test of `APP` (not part of `check`) |
| `make release-ios` / `make release-android` | `make check`, then fastlane build and upload to TestFlight / Play internal (`ENV=dev` or `prod`; see `docs/release.md`) |
| `make build-web` | release web build of `APP` |
| `make update-check` | report newer Flutter / dependency versions |
| `scripts/add-app <name>` | add another app to the workspace |

## Structure

```
apps/<app>/                 package <app>; default app: mobile
  lib/main.dart
  lib/app/                  composition root: app widget, router, providers (DI), AppEnv
  lib/features/<name>/      domain/ application/ data/ presentation/
  lib/l10n/                 ARB files + generated localizations (committed)
  test/ integration_test/ android/ ios/ web/
packages/
  app_ui/                   theme + atoms/ molecules/ organisms/ templates/ (no l10n: labels are parameters)
  app_shared/               domain/ (Result, Failure) and data/ (HttpClient port, dio and mock adapters)
scripts/                    init, add-app, update-check, check_architecture.dart, check_locales.dart
pubspec.yaml                workspace root listing every member
```

## Rules

- **Layers are enforced by `scripts/check_architecture.dart`** (part of `make check`), for every app and package it finds. Inside a feature: `presentation -> application -> domain <- data` (presentation may also use domain). A feature never imports another feature. Only `lib/app/` and `lib/main.dart` (the composition root) may import anything in their own app. Packages never import apps; an app never imports another app; `app_shared` never imports `app_ui`; `app_ui` may import `app_shared`.
- **Domain is pure Dart** (feature `domain/`, `app_shared/lib/domain`): no Flutter, dio, riverpod or other packages; only `dart:` core libraries, its own domain and `app_shared` domain.
- **Ports and adapters**: the port is an interface in `domain/` (or `app_shared/lib/data` for shared ones); adapters are prefixed `http_` or `mock_`. Providers in `lib/app/providers.dart` pick the adapter. Mocks are the default (`AppEnv.useMocks`) so apps run with no backend.
- **Expected failures return `Result<T>`** with a sealed `Failure`; do not throw for them.
- **`app_ui` has no localization**: widgets take labels as parameters; the app passes localized strings.
- **Each dependency is declared only in the members that use it**, with the same constraint everywhere (the check fails otherwise). Workspace members depend on each other as `name: any`. Versions live in the pubspecs and `.fvmrc`.
- **No codegen in the skeleton.** Providers and routes are hand-written. If you add codegen (see the `add-feature` skill), commit the generated files so a fresh clone runs without a generation step. gen-l10n output in `lib/l10n/` is committed; regenerate with `fvm flutter gen-l10n` inside the app folder.
- **Reuse before writing**: find the widget in the index blocks of this file first. If the product depends on a UI package that has its own index block here, that package comes first: use its widgets and style parameters, and let `app_ui` only compose them or add what the package lacks. Do not rebuild a package widget because one detail differs: try its parameters, then write only the missing detail by hand and mark it `// TODO(library: <what is missing>)` (say what you tried), and report the gap to the package's maintainers. `make check` lists the open markers.
- **Raw widgets**: raw Flutter widgets that have an `app_ui` replacement are rejected by `scripts/check_architecture.dart`. When a new `app_ui` widget replaces a raw Flutter widget, add it to the replacement map there. A package that ships its own raw-widget check (run it from `make check`) owns the replacements for its widgets.
- **Locale parity**: every ARB file of an app has the same keys (`scripts/check_locales.dart`). Add keys to all files together; no hard-coded UI strings.
- File names are snake_case; the folder names the role, so no role suffixes (`domain/user.dart`). Use `package:` imports only.
- Environment values are read once in `AppEnv`; never call `fromEnvironment` elsewhere.
- Package names `mobile`, `app_ui`, `app_shared` are internal and never renamed.

## Starting a project

Run once after cloning, from the repo root:

```
scripts/init --name my_app --org com.mycompany
```

It sets the workspace name, the mobile app's Android/iOS identifiers (`<org>.<name>`), display names and web title, rewrites the README, removes `LICENSE` and itself, and starts a fresh git repo. Use `--nested` when the workspace lives in a subfolder (`<product>/app/`) of a larger repo.
